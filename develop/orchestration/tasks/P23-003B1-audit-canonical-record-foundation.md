## In Scope

### 1. Trusted finalization

`AuditRecordStamp`はclosed `{recordId,recordedAt}` valueである。

- `recordId`: canonical lowercase UUIDv7
- `recordedAt`: UTC RFC3339、exact six fractional digits

`AuditRecordFinalizer::finalize(AuditRecordDraft, AuditRecordStamp)`はDraftの
`toArray()`をexactly once読み、exact14 Logical candidateを一度だけ組み立てる。
`time`は`{occurredAt,recordedAt}`であり、top-level `occurredAt|recordedAt`を残さない。
FinalizerはAccepted A2 `AuditRecordValidator::validateLogical()`をexactly once呼び、
そのdetached snapshotと同一definitionだけから`CanonicalAuditLogicalRecord`を作る。

`CanonicalAuditLogicalRecord`はAccepted A2 `AuditLogicalRecord`を実装する。
元Draft、candidate array、Validator、Catalog lookupへのreferenceを保持しない。
Productionでcandidateを作るのはFinalizerとRecordCodecだけとし、Architecture testで
それぞれのbounded callsiteを固定する。

Finalizerはcanonical UUIDv7 segment ID、maximum JSON-safe sequence、non-null
previous hash、maximum hash fieldsを使ったsynthetic complete recordもsize-checkする。
logical inputが有効でも将来の
canonical appendで1 MiB capを超えるものは`jcs_bound_invalid`で拒否する。

### 2. Partition and chain

`{type,id}`を使い、D148のtyped encodingとSHA-256式でexact 71-byte partition IDを

### 4. Shared BOPD binary primitive

Existing `BopdEnvelopeCodec`からBOPD v1 binary primitiveを一つだけ抽出する。

`BopdBinaryEnvelopeCodec`は次のexact callableだけを持つ。

```text
keyIdFromHeader(string prefix): string
parse(string envelope, int maxEnvelopeBytes): BopdBinaryEnvelope
seal(string plaintext, string aad, StorageKey key, string nonce,
     int maxPlaintextBytes, int maxEnvelopeBytes): string
open(BopdBinaryEnvelope envelope, string aad, StorageKey key,
     int maxPlaintextBytes): string
```

`keyIdFromHeader()`は既存rotation queryが取得するpartial prefix専用であり、magic、
version、algorithm、key ID length／grammarだけを検証する。Key ID 1／128 bytesを受理し、
既存wrapperの同名methodはこのprimitiveへ委譲する。

一つのfull-envelope operationで`parse()`はexactly onceである。Primitiveは次だけを所有する。

- BOPD magic／version／algorithm／key ID／nonce／ciphertext length／tagのparse
- XChaCha20-Poly1305-IETF seal／open
- existing length、nonce、tag、key-ID grammar
- trailing／truncated／overflowのfail-closed rejection

Primitiveはpurpose、tenant、row、KeySource、metricsを知らない。
Existing `BopdEnvelopeCodec`のpublic／internal signature、exception、metrics attributes、
known-answer bytesを変更しない。`StoragePurpose` exact9を変更しない。

Generic wrapperがprimitiveへ渡すliteralはplaintext／ciphertext cap
`0xFFFF_FFFF`とfull-envelope cap `0x1000000B3`
（`0xFFFF_FFFF + 52 + 128`）である。`52`はkey IDを除くBOPD v1 overhead、`128`は
maximum key ID bytesである。Audit専用1 MiB系capをgeneric wrapperへ流用しない。
巨大bufferを確保せず、private constant／checked additionと小さいinjected capの
boundary／cap+1で回帰を固定する。

### 8. Failure precedence and no-leak

Logical／JCS／hash validationはAccepted A1のten-stage safe codeを使う。

- temporal／partition／chain semantic: `semantic_invalid`
- logical／complete／ingress JCS cap: `jcs_bound_invalid`
- canonical content／record hash mismatch: `hash_mismatch`
- protection boundary: `protection_failed`

Unprotected writer precedenceはexactly
`logical validation -> logical cap -> chain-position validation -> hashes/integrity ->
complete cap -> ingress binding/caps -> key/encrypt`である。
Protected `unprotect*()`はpost-decrypt shape／canonical／hash mismatchも
`protection_failed`へ縮約する。

Protection exceptionはinput value、record／tenant／key ID、nonce、tag、ciphertext、
plaintext、hash、provider detail、previous exceptionを含めない。
Message、trace、`var_export`、`json_encode`、`serialize`、debug outputをcanaryで検査する。
